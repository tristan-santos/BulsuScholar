THREE ALGORITHMS USED IN THE LEVEL 1 DFD
============================================================

Algorithm 1: AES-256-GCM Password Encryption and Verification

Where it appears:
(1.0 Account Access and Authentication)
(7.0 Admin Management and Approval Operations)

Data flow:
[Student / Grantor / Admin]
--> password, login credentials, or password update
--> (1.0 Account Access and Authentication)
--> AES-256-GCM encrypt / decrypt / verify password
--> [[D1 Admin Accounts]]
--> [[D2 Student Accounts and Profiles]]
--> [[D4 Grantor / Provider Accounts]]

Description:
The system encrypts stored passwords using AES-256-GCM. During login, the encrypted password is decrypted and compared with the entered password. The same algorithm is used when admin creates or resets grantor accounts.

Input:
Plain password, stored encrypted password, system password secret

Output:
Encrypted Base64 password or true/false password verification result


Algorithm 2: Grantor-Scholar Matching and Duplicate Detection Algorithm

Where it appears:
(2.0 Student Registration and Profile Management)
(3.0 Scholarship Discovery, Selection, and Application)
(5.0 Grantor Scholar, Application, and Portal Management)
(7.0 Admin Management and Approval Operations)

Data flow:
[Student]
--> name, address, student number, email, contact number, course, year level
--> (2.0 Student Registration and Profile Management)
--> normalized matching and duplicate checking
--> [[D6 Grantor Scholars]]
--> [[D2 Student Accounts and Profiles]]
--> [[D13 Student Warnings / Compliance Records]]

Description:
The system compares student records with grantor scholar records. It normalizes names and addresses, checks exact name/address matches, and uses Levenshtein similarity with weighted fields to detect possible duplicate scholar records.

Input:
Student profile, grantor scholar records, address fields, identity fields

Output:
Matched grantor scholar, scholarship match, duplicate warning, or multiple-scholarship conflict warning


Algorithm 3: Scholarship Application Tracking and Status Progression Algorithm

Where it appears:
(3.0 Scholarship Discovery, Selection, and Application)
(4.0 Material Request, Download, and Compliance Checking)
(5.0 Grantor Scholar, Application, and Portal Management)
(7.0 Admin Management and Approval Operations)

Data flow:
[Student / Grantor / Admin]
--> application actions, document uploads, review stages, material requests, downloads, checking result
--> tracking status progression
--> [[D7 Scholarship Applications]]
--> [[D8 SOE and Application Form Requests]]
--> [[D9 SOE Downloads / Checked Materials]]
--> status, current step, next action
--> [Student / Grantor / Admin]

Description:
The system builds a scholarship tracking path depending on provider type. KWSP has a longer flow with admin review, interview, application review, and final screening. Other scholarships use the standard flow. The algorithm checks completed steps, document status, material request status, download status, and signing/compliance status to determine the current step.

Input:
Scholarship record, provider type, tracking history, document check, latest material request, latest SOE download

Output:
Current step, completed steps, owner of next action, status label, and whether the student/admin can proceed
