DETAILED LEVEL 2 ALGORITHMS USED IN THE SYSTEM
============================================================

ALGORITHM 1: AES-256-GCM PASSWORD ENCRYPTION AND VERIFICATION

Related Level 2 processes:
(1.3 Validate Credentials and Status)
(1.5 Process Password Reset or Password Change Request)
(7.3 Manage Grantors)

Algorithm flow:

[Student / Grantor / Admin]
--> plain password
--> (A1.1 Prepare Encryption Key)

(A1.1 Prepare Encryption Key)
--> read system password secret
--> pad or trim secret to 32 bytes
--> import key for AES-GCM encryption/decryption
--> (A1.2 Encrypt Password)

(A1.2 Encrypt Password)
--> generate random 12-byte IV
--> encrypt plain password using AES-GCM
--> combine IV + encrypted password
--> convert combined bytes to Base64
--> [[D1 Admin Accounts]]
--> [[D2 Student Accounts and Profiles]]
--> [[D4 Grantor / Provider Accounts]]

For login verification:

[Student / Grantor / Admin]
--> entered password
--> (A1.3 Decrypt Stored Password)

(A1.3 Decrypt Stored Password)
--> read encrypted Base64 password from user record
--> convert Base64 to bytes
--> split IV and encrypted password
--> decrypt using AES-GCM and same 32-byte secret key
--> (A1.4 Compare Passwords)

(A1.4 Compare Passwords)
--> compare entered password with decrypted password
--> true or false verification result
--> (1.3 Validate Credentials and Status)

Output:
Encrypted password for storage, or successful/failed login result.


ALGORITHM 2: GRANTOR-SCHOLAR MATCHING AND DUPLICATE DETECTION ALGORITHM

Related Level 2 processes:
(2.6 Match Student to Grantor Scholars)
(3.2 Check Student Scholarship Access)
(5.2 Add or Import Scholars)
(7.4 Manage Scholarships and Application Tracking)

Part A: Student-to-Grantor Scholar Matching

[Student]
--> first name, middle name, last name, full name, street, city, province, postal code
--> (A2.1 Normalize Student Data)

[[D6 Grantor Scholars]]
--> scholar first name, middle name, last name, full name, street, city, province, postal code
--> (A2.2 Normalize Scholar Data)

(A2.1 Normalize Student Data)
--> lowercase values, remove accents, remove special characters, trim spaces
--> (A2.3 Compare Names)

(A2.2 Normalize Scholar Data)
--> lowercase values, remove accents, remove special characters, trim spaces
--> (A2.3 Compare Names)

(A2.3 Compare Names)
--> if full names are equal, name match is true
--> else compare first name + last name
--> if middle initials both exist, compare middle initials
--> name match result
--> (A2.4 Compare Address)

(A2.4 Compare Address)
--> compare available street, city, province, and postal code fields
--> if any shared field differs, address match is false
--> if shared fields match, address match is true
--> if no shared individual field exists, compare combined full address
--> (A2.5 Confirm Grantor Match)

(A2.5 Confirm Grantor Match)
--> if name match is true and address match is true
--> matched grantor scholar
--> [[D2 Student Accounts and Profiles]]
--> [[D13 Student Warnings / Compliance Records]]

Part B: Duplicate Scholar Detection

[Grantor / Scholarship Provider]
--> imported or manually entered scholar record
--> (A2.6 Compute Duplicate Similarity)

(A2.6 Compute Duplicate Similarity)
--> compare candidate against existing scholar records
--> calculate Levenshtein similarity for:
    student ID, name, email, contact number, course, year level, city, province
--> apply weighted score:
    student ID = 0.32
    name = 0.30
    email = 0.10
    contact number = 0.08
    course = 0.08
    year level = 0.04
    city = 0.04
    province = 0.04
--> (A2.7 Decide Duplicate)

(A2.7 Decide Duplicate)
--> duplicate if exact student ID matches
--> duplicate if email or phone matches and name similarity >= 0.72
--> duplicate if name similarity >= 0.82 and weighted score >= 0.84
--> duplicate or non-duplicate result
--> [[D6 Grantor Scholars]]

Output:
Matched scholarship/grantor, duplicate warning, conflict warning, or accepted scholar record.
