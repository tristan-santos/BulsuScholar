============================================================
THREE ALGORITHMS USED IN THE SYSTEM
============================================================

Algorithm 1: AES-256-GCM Password Encryption and Verification

Purpose:
Protects locally stored student, admin, and grantor passwords by encrypting them before saving and decrypting only for password comparison during login.

Used in Level 0 flow:
[Student / Grantor / Admin]
--> login credentials or new password
--> (0.0 BulsuScholar System)
--> AES-256-GCM encryption / decryption / password comparison
--> [[D1 Admin Accounts]]
--> [[D2 Student Accounts and Profiles]]
--> [[D4 Grantor / Provider Accounts]]

Main steps:
1. Convert the system password secret into a 32-byte key.
2. Generate a random 12-byte initialization vector.
3. Encrypt the plain password using AES-GCM.
4. Combine IV + encrypted password.
5. Convert the result to Base64 for storage.
6. During login, decrypt the stored value and compare it with the entered password.


Algorithm 2: Grantor-Scholar Matching and Duplicate Detection Algorithm

Purpose:
Matches student registration/profile data with grantor scholar records and detects possible duplicate scholar entries.

Used in Level 0 flow:
[Student]
--> registration/profile details
--> (0.0 BulsuScholar System)
--> name normalization, address matching, Levenshtein similarity, weighted duplicate score
--> [[D6 Grantor Scholars]]
--> [[D2 Student Accounts and Profiles]]
--> [[D13 Student Warnings / Compliance Records]]

Main steps:
1. Normalize names and addresses by converting to lowercase, removing accents, and removing unnecessary symbols.
2. Compare full name or first name + last name + middle initial.
3. Compare available address fields: street, city, province, and postal code.
4. Match student with active grantor scholar records when name and address match.
5. For duplicate scholar checking, compute Levenshtein similarity for name, ID, email, phone, course, year level, city, and province.
6. Apply weighted scoring and mark as duplicate when strong identifier or high weighted similarity is reached.


Algorithm 3: Scholarship Application Tracking and Status Progression Algorithm

Purpose:
Determines the current scholarship stage, completed steps, next action, and displayed status for each scholarship application.

Used in Level 0 flow:
[Student / Grantor / Admin]
--> application actions, document uploads, material requests, approvals, downloads, checking result
--> (0.0 BulsuScholar System)
--> tracking step evaluation and status progression
--> [[D7 Scholarship Applications]]
--> [[D8 SOE and Application Form Requests]]
--> [[D9 SOE Downloads / Checked Materials]]

Main steps:
1. Identify the scholarship flow type: KWSP flow or standard scholarship flow.
2. Build the correct ordered step list.
3. Mark system/student/admin-completed steps.
4. Check document completion, material request status, approved materials, downloaded materials, and signing/compliance result.
5. Find the first incomplete or attention-needed step.
6. Return current step label, owner, status label, next action, and whether admin or student can proceed.
